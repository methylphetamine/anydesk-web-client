◇ the flow

One field, two ways in

The honest version of "web client": hand off to the real app when it exists, fall back to a browser session when it doesn't.

  1. 01

    Address

    Nine or ten digits, or an alias. The field formats digits and validates the shape — locally, with no request.

  2. 02

    Handoff

    Open in AnyDesk navigates to anydesk:<address>. The installed client takes over, shows the usual accept/password prompt, and runs the session natively.

  3. 03

    Fallback

    Without AnyDesk, the other side can share this desk and you watch the screen over WebRTC — view-only, because browsers cannot inject input.

◇ scope

What this is — and what it isn't

It is

  • A real launcher: the same anydesk: URL handler AnyDesk documents for links and the my.anydesk portal
  • A working browser viewer for peer-to-peer screen sharing, gated by address and code
  • Static — it runs on GitHub Pages with no backend and no analytics

It isn't

  • An AnyDesk protocol client: a web page cannot speak their closed, encrypted protocol to an arbitrary ID
  • Usable without the app installed — the handoff needs a registered anydesk: handler
  • A remote-control surface in browser mode: capture is view-only by design

Need browser access tied to your own devices? That is my.anydesk II, AnyDesk's official web client (account required). Need the download? anydesk.com/downloads.

◇ security

Why the password never touches this page

AnyDesk handles authentication itself. A website that asks you to type an AnyDesk password into a web form is a phishing page, not a client.

Handoff path

  • The page only builds anydesk:<address> — no network request, no credentials
  • The native app shows the accept dialog or unattended-password prompt, exactly as if you typed the ID there
  • Permission, file transfer and session recording all stay under AnyDesk's own security model
  • If no handler is registered, the browser asks what to do; the page offers a copy fallback and a download link

Browser-viewer path

  • Media is encrypted in transit with DTLS-SRTP; frames never pass through a server
  • The host refuses viewers without the six-digit code — the address alone is not enough
  • Signalling uses the public PeerJS broker; self-host it for anything serious
  • This is a demo, not an audited product: no consent queue, no audit log, no recording
