    ◇ the flow

    Three steps, zero downloads

    That is the shape of a browser remote-desktop client. Here it runs end-to-end against a canvas.

    1. 01

      Address

      Nine digits identify a desk. This demo validates and formats the address, then remembers it locally.

    2. 02

      Handshake

      The connecting screen walks through address resolution, session negotiation and screen setup — timed animations, not sockets.

    3. 03

      Session

      A canvas paints the remote desktop, a toolbar carries quality, chat and info, and a ticker keeps the counters alive.

    ◇ scope

    What this is — and what it isn't

    It is

    • A static, dependency-free front end for a remote-desk console
    • A reference for connection UX: validation, handshake, session chrome
    • Private by construction — no network calls, no analytics, no backend

    It isn't

    • A working AnyDesk client — their protocol is closed and needs a native agent
    • A way to control another machine, or to receive incoming connections
    • Affiliated with, endorsed by, or built from AnyDesk GmbH code

    Need the real thing? Use AnyDesk's official clients. Want real browser-to-browser screen sharing? Wire this UI to RTCPeerConnection + getDisplayMedia().
